5. 발견된 튜너 문제와 수정
============================================================
1) 프로필 간 비용 window 오염
- 앞 profile에서 증가한 노드가 다음 profile 시작 시 남아 다음 비용 점수를 오염함.
- 최초 measured low-load node floor와 HPA min으로 복귀하도록 최대 360초 cooldown 추가.
- timeout 시 증거를 남기고 다음 프로필 진행.
- commit: be0913a

2) HPA Max 정책
- Max는 저부하 제어값이 아니라 고부하 ceiling임.
- 성능 guard 실패 + 실제 Desired>=Max/CPU>target에서만 Max 증가 후보 생성.
- guard 통과 시 measured peak desired + 20% headroom보다 과도한 Max만 one-delta 축소.
- Min은 별도 one-delta로 저부하 비용 최적화.
- commit: be0913a

3) 순간 RPS 흔들림 오판
- BASE 완료 후 최종 순간 status sent_rps=4 / target_rps=4.6을 전체 run generator limit으로 잘못 판정해 application candidate 없이 중단됨.
- run 누적 dropped>0만 generator saturation으로 판정하도록 수정.
- 정상 instantaneous RPS jitter는 탐색을 중단하지 않음.
- self-test 22/22 PASS.
- commit: e704c1e

7. 연속 탐색 원칙
============================================================
- 매 candidate는 measured BEST의 정확한 copy에서 one-delta만 변경.
- 각 candidate마다 Default, Default-spike2, 순차증가를 모두 fresh 실행.
- 세 profile performance/availability guard 우선.
- primary score는 세 profile TotalScore 중 최저값.
- 한 profile만 좋아지고 최저 profile이 나빠지면 REJECT.
- KEEP이면 measured BEST 갱신, REJECT이면 BEST rollback.
- 최종 선택 후에도 FINAL_FRESH 세 profile을 실제 재실행.
- resource loss, AWS credential 만료, EKS/RDS 삭제 외 recoverable failure는 증거 저장 후 다음 iteration 계속.
